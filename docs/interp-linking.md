# 司法解释如何“挂”到法条下

**法律总览页（`/d/:docId`）的结构**：先给“怎么读这本书”——左侧 sticky 侧栏是**目录树**（编 → 分编 → 章 → 节，最深到节，可逐级展开收起，并按当前浏览位置自动展开与高亮），右侧是条文目录窗口（分页 + 本书内筛选，换章换节处插入章节标题分隔行，翻页正好落在章节中间时标题追加一个“续”徒标）；关联区**排在目录之后**，形成“读原文，再看关联”的顺序：

1. **关联法条**（司法解释与行政法规）：按法律分组的法条标签，条文标签直接用正式条号，按引用次数排序、超过 8 条折叠；法名标签悬停给出说明（`tags.json`，见 data-model）。
2. **本书的疑难注解**：本书全部人工注解（`curated`）的入口，带重要度徒标。
3. **关联司法解释**：标题带件数，逐件列出文书链接与“关联条文 N 条 · N 处引用”及最高关联强度；超过 80 件时先列前 80 件。
4. **关联指导性案例**：适用本书条文的案例。
5. **数据说明**（如有）：无法自动定位的条号引用。

**侧栏目录顶部有区段跳转**（“关联法条 N / 疑难注解 N / 关联司法解释 N / 指导性案例 N / 数据说明”），只列出本文档实际存在的区；区末尾有“↑ 回到条文目录”回到 `#toc`。

**目录树（编 → 分编 → 章 → 节，最深到节）**：直接按条文自带的 `path` 分层渲染成 `<details>` 嵌套列表，章节节点右侧标出**条文数**；最深一层（节，或没有节的章）渲染成一行链接（`toc-end`），不再逐条铺开（民法典 1260 条逐条铺开会撑成十几屏）：

- **层级可展开收起**：全用原生 `<details>/<summary>`，禁用 JS 也能用；只有还有下级的节点才套 `<details>`，最深层直接给一行链接；点章节标题文字只开合，点节点上的链接则跳转。
- **按当前位置自动展开 + 高亮**：服务端先按窗口首条找到它所属的**最深那个章节**（将该链上的各级展开为 `<details open>`，给该章节标 `is-current`、给祖先标 `is-on-path`）；若落在页内锚点（如 `?from=301#a277`），前端以那条条文为准修正到它所在的章节并展开；页内滚动时高亮与展开跟着走（滚动跟随），只在“高亮行看不见”时才自动滑动侧栏，不抢用户的滚动。
- **没有章节结构的文件自动平铺**：全库 197 部（大多是司法解释）完全没有 `path`，只能平铺条文（`is-flat`），否则目录会是空的；另有 24 部是混合的（前几条没有章节标题），这些条文单独占一行（“其他条文”桶），与有章节的分支并列。
- **翻页感知**：条文窗口只渲染 100 条，所以目录里的章节链接不能一律写成 `#a277`（那个锚点根本不在本页）：
  - 目标在本页 → 普通 `#a…`，不重走一趟服务端；
  - 目标在别页 → 链到 `/d/:docId?from=277#a277`，`from` 直接取**该章节首条的下标 + 1**，于是落地页服务端渲染出来的目录就已经把这一章节标成当前位置（不依赖前端 JS 修正），行尾再给一个淡色“第 5 页”提示；
  - 本节内筛选（`&q=`）时只列出命中条文所在的章节（树自动剪枝），目录下方注明“其余章节已隐藏”，不产生任何死链接。

一份条文页（如 `/d/civil-code?a=585`）从上到下是：

1. **条文原文**（款分行、可复制、可分享锚点）
2. **疑难注解**（人工撰写）：问题、分析、要点、易错点、其他参考、关键词；没有人工注解的条文整块不显示
3. **关联的司法解释（N 件 / M 处）**：按司法解释文书分组，组内给出条号、可靠度徽标与提及次数，不展开条文原文；区块顶部是关联强度说明
4. **关联的指导性案例（N 件）**
5. **本条引用的其他条文（N 条）**：本条正文引用、且能在库内定位的其他条文

反过来，司法解释的条文页（如 `/d/sfjs-mfd-hetong/64`）会展示它**解释了哪些法条**，形成双向可追溯。司法解释的**总览页**则把概览反过来数（标题叫“引用概览”；法律页不再有“关联概览”区块）：涉及法律 N 部 / 引用条文 N 条 / 条文级关联 N 处（另计数“引用其他司法解释”的处数），与页头的“查看《民法典》”按钮（只在标题能确定解释对象时出现）一起，让人一眼看出这部解释在解释哪部法律；它引用过的全部法律与条文统一放在“关联法条”标签区。
