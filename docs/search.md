# 全局检索

## 检索什么

条文正文（权重最高）、条号、法名/简称、注解主题与要点、关键词、案例标题与裁判要点。一次检索同时命中这六类内容，并在结果里标出**命中字段**。

## 可指定的范围与排序

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `scope` | `all` / 编 id（`constitutional` `criminal` `civil` `commercial` …） | 按编限定 |
| `type` | `all` / `宪法` `法律` `行政法规` `司法解释` | 按文件类别限定 |
| `annotated` | `1` | 只看有疑难注解的条文 |
| `doc` | 文档 id | 只在某一部法律内检索 |
| `sort` | `relevance`（默认）/ `hierarchy` / `date_desc` / `date_asc` / `annot` / `order` | 相关度、法律位阶、颁布时间、注解优先、按法律名+条号 |
| `page` / `pagesize` | 整数 | 分页（默认 20/页，上限 100） |
| `q` | 关键词 | 见下文“查询写法” |

> 扩展位：`sort` 与 `scope` 都是**白名单 + 表驱动**（`server/search.js`），新增一种排序只需要加一个比较函数与一个标签。

## 查询写法

- **“法名 + 条号”直接定位**：`民法典第585条`、`民法典585条`、`刑法 20`（简称、阿拉伯数字、省略“第”都认）→ 结果页顶部弹出“直接定位：民法典 第 585 条”。若法名有歧义（如“合同法”同时匹配多个文件），会把**其他候选**一并列出并标注。
- **多词**：空格分词，全部命中才算（AND），并按命中密度、字段权重、条文长度做长度归一，避免长条文刷分。
- **拉丁字母大小写不敏感**：`DNA` / `dna` / `Web` / `GB/T` 结果相同——语料入库时另存一份全小写副本专供匹配（展示与高亮仍用原文，不会把条文变成小写）。
- **分面**：结果页给出类别/编/文档的命中数，可直接点选收窄（如“司法解释 37”）。
- **快照高亮**：命中词在结果摘要里 `<mark>` 标出，摘要围绕首次命中位置截取。

## 检索实现要点（`server/search.js`）

- **不建倒排索引**：把查询切成中文二元组（bigram）+ 英文/数字词元，对 3 万条条文线性扫描，实测单次约 60–90 ms（约 4.6M 字），换来的是“改任何字段立刻生效”。响应里带 `ms`（本次扫描耗时，毫秒）与 `scanned`（候选池大小，等于本次参与扫描的条文数）——因为每条候选都会扫一遍，`scanned` 只反映范围/类型/文档限定，所以界面上显示的是 `ms`。
- **匹配用小写副本**：`db.corpus` 的每条记录额外带 `textLower` / `titleTextLower` / `annotTextLower`（入库时算一次），匹配、短语加权、快照定位都读它们；命中后再用原文域生成摘要，所以不会出现“命中大写写法却搜不出来”或“条文被小写化”。
- 排序：`relevance` = 字段权重 × 命中次数（上限 6）× 长度归一 + 关联/注解加成；`hierarchy` 按“宪法 → 法律 → 行政法规 → 司法解释”的效力层级。
- 空查询 = 浏览模式：直接按所选排序翻遍全库。
