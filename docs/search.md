# 全局检索

## 检索什么

条文正文（权重最高）、条号、法名/简称、条旨、注解主题与要点、关键词、案例标题与裁判要点。一次检索同时命中这七类内容，并在结果里标出**命中字段**（快照取自哪一类：标题、条旨、注解或正文）。

## 可指定的范围与排序

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `scope` | `all` / 编 id（`constitutional` `criminal` `civil` `commercial` …），可多选 | 按编限定；重复参数（`scope=civil&scope=social`）勾选多个编，同一维度内取并集，也兼容逗号分隔 |
| `type` | `all` / `宪法` `法律` `行政法规` `司法解释` `指导性案例`，可多选 | 按文件类别限定；重复参数（`type=法律&type=司法解释`），同一维度内取并集，也兼容逗号分隔 |
| `annotated` | `1` | 只看有疑难注解的条文（裁判文书没有注解，`gazette=1` 时该项不生效） |
| `gazette` | `1` | **只在《最高人民法院公报》裁判文书里检索**；不勾选时裁判文书完全不参与检索（默认候选池 = 条文 + 指导性案例） |
| `doc` | 文档 id | 只在某一部法律内检索 |
| `sort` | `relevance`（默认）/ `hierarchy` / `date_desc` / `date_asc` / `annot` / `order` | 相关度、法律位阶、颁布时间、注解优先、按法律名+条号 |
| `page` / `pagesize` | 整数 | 分页（默认 20/页，上限 100） |
| `q` | 关键词 | 见下文“查询写法” |

> 多选口径：`scope` 与 `type` 各自内部取并集，两者之间取交集；即 `scope=civil&scope=social&type=法律&type=司法解释` 表示“（民法 或 社会法）且（法律 或 司法解释）”。表单里是两个可勾选多个的下拉框，勾选即生效。

> 扩展位：`sort` 与 `scope` 都是**白名单 + 表驱动**（`server/search.js`），新增一种排序只需要加一个比较函数与一个标签。

## 查询写法

- **“法名 + 条号”直接定位**：`民法典第585条`、`民法典585条`、`刑法 20`（简称、阿拉伯数字、省略“第”都认）→ 结果页顶部弹出“直接定位：民法典 第 585 条”。若法名有歧义（如“合同法”同时匹配多个文件），会把**其他候选**一并列出并标注。
- **文件标题全名**：`最高人民法院关于适用〈中华人民共和国民事诉讼法〉的解释` → 顶部列出“直接命中文件”，且该文件的条文整体排在其它结果之前。书名号《》〈〉、括号纪年在比对时一律忽略，简称与别名（`民诉解释`）同样算精确命中。
- **多词（默认 OR）**：空格分词，任一命中即入选——`学术 教育 处罚` 返回含这三个词中任意一个的条文，命中词数多的排在前面。要“与”就写 `AND`：`学术 AND 教育 处罚` 是“学术 ∧ 教育，或 处罚”。单个词内部切成中文二元组后，2 个以内要求全中、3 个以上要求 60%（`need = n <= 2 ? n : ceil(n * 0.6)`），所以“违约金”按“违约 + 约金”两个二元组判定；二元组不要求字符串连续（“违约定金”也能满足“违约金”）。命中密度、字段权重、条文长度仍参与长度归一，避免长条文刷分。
- **`AND` / `OR` / `NOT` 运算符（必须大写、前后留空格）**：空格本身就是“或”，`OR` 可省略（`违约金 OR 定金` 与 `违约金 定金` 等价）；`AND` 表示“与”（`违约金 AND 定金`）；`NOT` 排除紧随其后的一个词，并与当前一组结合——`违约金 NOT 定金` 即“违约金 且不含定金”，放在开头则等价于“浏览不含该词的全部条文”。优先级：`NOT` 高于 `AND`，`AND` 高于空格 / `OR`，`违约 AND 解除 赔偿` 等价于 `(违约 AND 解除) OR 赔偿`；不支持括号。引号里的 `AND` / `OR` / `NOT` 不是运算符；小写 `and` / `or` / `not` 按普通检索词处理。中文“或 / 非 / 和”没有运算符含义（“或”仍按停用字忽略）。
- **拉丁字母大小写不敏感**：`DNA` / `dna` / `Web` / `GB/T` 结果相同——语料入库时另存一份全小写副本专供匹配（展示与高亮仍用原文，不会把条文变成小写）。
- **分面**：响应里的 `facets` 仍给出类别/编的命中数，供 API 客户端使用；检索页不再渲染分面标签，筛选走表单里的下拉框。分面数字只按**另一个**维度统计（编的分面数忽略当前编、类别分面忽略当前类别），多选时可以看出“再加一个会得到多少”。
- **快照高亮**：命中词在结果摘要里 `<mark>` 标出，摘要围绕首次命中位置截取。摘要优先取正文，标题行（法名 + 条号 + 编章节目录）只在正文、条旨、注解都没命中时兜底——否则搜“管辖”这类也出现在章节名里的词，摘要会退化成目录行。响应里的 `snippet.field` 标出摘要取自哪一类（`text` / `rubric` / `annot` / `title`），页面不显示这个标签。

## 检索实现要点（`server/search.js`）

- **不建倒排索引**：把查询切成中文二元组（bigram）+ 英文/数字词元，对 3 万条条文线性扫描，实测单次约 60–90 ms（约 4.6M 字；勾选裁判文书后只扫 445 篇文书、约 475 万字，实测数毫秒级），换来的是“改任何字段立刻生效”。候选池按 `gazette` 二分：默认池是 30,347 条（条文 + 指导性案例），勾选后是 445 篇裁判文书——两类互斥，裁判文书不会混进默认结果。响应里带 `ms`（本次扫描耗时，毫秒）与 `scanned`（候选池大小，等于本次参与扫描的条文数）——因为每条候选都会扫一遍，`scanned` 只反映文档（`doc`）、裁判文书与注解限定，不再随范围/类型收窄（这两项在扫描后过滤），所以界面上显示的是 `ms`。
- **匹配用小写副本**：`db.corpus` 的每条记录额外带 `textLower` / `titleTextLower` / `annotTextLower` / `rubricTextLower`（入库时算一次），匹配、短语加权、快照定位都读它们；命中后再用原文域生成摘要，所以不会出现“命中大写写法却搜不出来”或“条文被小写化”。
- 字段权重：标题 6、条旨 5、注解 4、正文 2.5。条旨先按 `rubricByArticle` 挂到条文上再进 `corpus`，所以条旨与条文永远同一条记录，不需要额外索引。
- 排序：`relevance` = 字段权重 × 命中次数（上限 6）× 长度归一 + 关联/注解加成；比较时**先看 `tier`**——文件标题精确命中（`documentMatches` 的 level 0）时该文件的条文 `tier=0`，排在所有 `tier=1` 的结果之前；接着看**命中的词数**（多词查询里命中词多的优先），最后按分数、位阶、颁布时间。`hierarchy` 按“宪法 → 法律 → 行政法规 → 司法解释”的效力层级。
- `docHits`：`documentMatches` 命中的文件（level ≤ 1，最多 5 个）随响应返回，供页面顶部渲染“直接命中文件”；`doc` 限定检索、`gazette=1` 以及查询里含 `AND` / `OR` / `NOT` 时为空数组。
- **查询解析**：`splitUnits` 按空白切分（引号内不切），`parseQuery` 把词元组装成若干“OR 分支”：空白或 `OR` 开新分支，`AND` 把下一个词留在当前分支，`NOT` 把下一个词记为当前分支的排除项（分支为空时单独成一个纯排除分支）。分支内的正词全部命中才算该分支命中（每个词的二元组口径同上），排除项的全部二元组都出现则整条排除。条文命中任一分支即入选，排序时先比命中的分支数（命中词数多者优先），再比分数；多个分支命中时分数相加，`hits` 只收正词；含显式运算符的查询不再做文件标题精确命中，相关度排序的 `tier` 恒为 1。
- **范围/类型在扫描后过滤**：`search()` 先扫候选池并按查询匹配，再按 `scopes` × `types` 求交集得到结果；`splitList` 同时接受数组与逗号串，忽略 `all` 与空值。响应里的 `facets` 用两份匹配集统计：类别数取自“只按编过滤”的集合，编数取自“只按类型过滤”的集合。
- 空查询 = 浏览模式：直接按所选排序翻遍全库。
